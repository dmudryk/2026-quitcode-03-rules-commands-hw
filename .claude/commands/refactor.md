# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу після
назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Зафіксуй «до»** і запиши числа, вони знадобляться в кінці:
   ```bash
   cd app && npm run check:rules && npm test
   ```
   Виpиши окремо кількість порушень саме для цільового файлу (розділ `by file`).
2. Прочитай цільовий файл, його тест (`<ім'я>.test.ts`) і сусідній модуль, який уже
   відповідає конвенціям, — як взірець форми.
3. Склади список порушень цільового файлу з виводу `check:rules` і для кожного визнач
   заміну за правилами проєкту (`.claude/rules/conventions.md`,
   `.claude/rules/architecture.md`). Правила не переписуй сюди — посилайся на них.
4. **Збережи поведінку.** Незмінними лишаються: URL запиту (включно з query-параметрами
   і їх порядком), метод, заголовки, форма й порядок полів у тілі, тексти повернутих
   помилок, порядок і умови викликів. Рефакторинг — це та сама поведінка іншим кодом.
5. Правь **лише цільовий файл**. Якщо для нього потрібна зміна в іншому місці — назви її
   й зупинись; не розширюй обсяг самовільно.
6. **Асерти в тестах не редагуй.** Тест — це фіксація поведінки: якщо він падає, це
   рефакторинг зламав поведінку, а не тест застарів. Додати новий тест можна; змінити
   наявний асерт — ні.
7. **Зафіксуй «після»** тими самими командами й порівняй числа.

## Acceptance criteria

- [ ] `cd app && npm test` зелений; кількість тестів і асерти ті самі, що до запуску.
- [ ] `cd app && npm run typecheck` чистий.
- [ ] `cd app && npm run check:rules`: порушень для цільового файлу стало менше
      (в ідеалі `0`), у жодному іншому файлі не побільшало.
- [ ] `git diff --name-only` показує лише цільовий файл.
- [ ] Жодного шляху з `.claude/rules/do-not-touch.md` у діфі.

## Stop

Якщо `npm test` після рефакторингу падає — не «підправляй» тест і не міняй асерт:
поверни файл (`git checkout -- <файл>`), покажи, який саме асерт упав і чому,
і зупинись. Якщо порушення неможливо усунути без зміни в захищеній зоні —
опиши потрібну зміну і зупинись, чекаючи підтвердження людини.
