# Конвенції коду lead-sync

## Контекст

Воркер працює в production без нагляду, тому помилки мають бути видимими значеннями,
а не винятками, і кожна небезпечна операція (HTTP, змінні середовища, парсинг, журнал)
проходить через один модуль ядра з таймаутами, повторами й маскуванням секретів
(`materials/architecture-brief.md`, розділ «Конвенції коду»). Статична перевірка цих
конвенцій — `app/scripts/check-rules.mjs`.

## Правило

- **Помилки — це значення.** Функція, що може не вдатися, повертає `Result<T>` з
  `core/types.ts`. `send()` інтеграції не кидає винятків назовні — завжди
  `Promise<Result<void>>`; помилка повертається як `{ ok: false, error: "..." }`.
- **Вихідний HTTP — лише `postJson()`** з `app/src/core/http.ts`. Прямий `fetch` не
  використовуй: у ньому немає таймауту, повторів на 5xx/429 і маскування URL у журналі.
  Нових HTTP-клієнтів (`axios`, `got`, `ky`) не додаємо.
- **Змінні середовища — лише `readEnv()`** з `app/src/core/config.ts`. `process.env`
  поза `core/config.ts` не читаємо. Значення секретів не пишемо в журнал і не вшиваємо
  в код, навіть тимчасово; у `requiredEnv` — лише імена змінних.
- **Зовнішній JSON — лише `parseJson(text, guard)`** з `app/src/core/parse.ts`, з guard
  на очікувану форму (`isRecord`, `isString`, `isNumber`). `JSON.parse` не використовуй.
  Невалідний JSON або неочікувана форма — це `Result` з `ok: false`, який видно в
  журналі. Тихо підставити «значення за замовчуванням» і працювати далі не можна:
  саме так пошкоджений стан стає непомітним.
- **Журнал — лише `log.info` / `log.warn` / `log.error`** з `app/src/core/log.ts`.
  `console.*` не використовуй: `log` маскує токени, `console.log` друкує їх як є.
- **Без `any`:** ні `: any`, ні `as any`, ні `<any>`. Для невідомих даних — `unknown`
  плюс guard.
- **Без нових залежностей.** У `app/` нуль runtime-залежностей, і так має лишитись.
  Потрібна бібліотека — спершу питання в PR, а не `npm install`.
- **Мінімізація даних.** У сповіщення (Slack, месенджери) передаємо лише `name`,
  `source` і `budgetUsd`. `lead.email` і `lead.phone` туди не потрапляють — повні дані
  йдуть лише в системи обліку (таблиця, CRM).
- **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу.
- **Тести.** Vitest, `*.test.ts` поруч із модулем, без реальної мережі: `fetch` — через
  `vi.stubGlobal("fetch", ...)`, змінні — через `vi.stubEnv`. Для кожної інтеграції три
  випадки: успішна відправка (перевірити URL і тіло запиту), відсутня змінна середовища,
  помилка від зовнішньої системи.
- **Легасі** (код, перенесений з n8n до появи цих конвенцій) приводимо до конвенцій
  **без зміни поведінки**, яку фіксують тести: URL, тіло запиту, тексти помилок
  лишаються тими самими, асерти в тестах не редагуємо.

## Як перевірити

- `cd app && npm run check:rules` → `0` у рядках `http-via-core`, `env-via-config`,
  `json-via-parse`, `log-via-logger`, `no-any`, `no-new-deps`.
- `cd app && npm test` — зелено; після рефакторингу число тестів і асерти не змінились.
- `cd app && npm run typecheck` → чисто.
- `git diff app/package.json` → блок `dependencies` не з'явився.
